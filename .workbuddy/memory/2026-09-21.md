## 做了什么

### 1. POST /storage 补齐服务端校验（安全修复）
- 原状：完全没有请求体校验。缺 file/key → TypeError → 500；
  且 `file.type` 原样写入对象存储 Content-Type，而 `/api/blob/*` 原样回显该头，
  **上传 text/html 可构造同源存储型 XSS**。
- 修复：file 存在性校验 → 400；5MB 上限（对齐 client `DEFAULT_IMAGE_MAX_FILE_SIZE`）；
  `image/*` 白名单（对齐 client `isImageFile`，解析时去掉 `;charset=` 参数）；
  blob 响应统一附加 `nosniff` + `CSP default-src 'none'; sandbox`（兜住 SVG 等可脚本类型）。
- 附带完善：key 缺失回退 `file.name` 推断后缀；无后缀不再生成 `hash.` 结尾。
- 唯一消费者是 client `image-upload.ts`（图片上传），已确认 theme/docs 无其他调用方。

### 2. GET /tag/:name 的 decodeURI 缺保护
- 字面 `%`（`%25`）会抛 URIError → 500；而 `/search/:keyword` 早先已修同类问题。
- 抽出 `decodePathParam`（`server/src/utils/path.ts`）供 tag 与 search 共用，避免再次只修一处。
