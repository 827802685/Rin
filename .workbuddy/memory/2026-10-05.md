## 本次改动

### 1. fix(feed)：文章 UV 永久少计 1（`52a73fe`）

`server/src/services/feed.ts` 的 `GET /:id` 里，首次访问创建 `visit_stats` 的分支
只写了 `new HyperLogLog().serialize()`（空 sketch），**没有把当前访客 `add` 进去**，
`uv` 还被硬编码成 `1`。

后果：第一个访客的 IP 永远不进 HLL。只要他之后不再访问这篇文章，该文章的 UV
从此恒定少 1 —— 小流量文章尤其明显（真实 2 个访客只报 1）。

修复：创建分支与更新分支对称——`const hll = new HyperLogLog(); hll.add(visitorKey);`，
`uv` 改由 `Math.round(hll.count())` 取。

## 已知限制

   会互相覆盖，丢 PV 也丢 UV 增量。D1/SQLite 没有 HLL 的原子累加原语，
   要根治得改成「追加一条 visits 记录 + 异步聚合」，本次未做。

## 本轮经验（供后续复用）

1. **变异测试不要用 `git checkout -- <file>` 还原**——它会把尚未提交的修复一起抹掉。
   本轮实际踩到：UV 修复被还原，visit-stats 从 6 绿退回 3 红，只能重新应用。
   要么先提交再变异，要么手工备份再还原。
2. **Python 读写 CRLF 源码必须 `io.open(p, encoding='utf-8', newline='')`**：
   默认的 universal newlines 会把 `\r\n` 吃掉，导致 `str.count(old)==0` 静默失败。
3. **写 UV 断言时，第一个访客绝不能在后面被重复访问**——回访会把漏记的那个访客
   补进 HLL，让有 bug 的实现照样给出正确答案（假绿）。设计用例时必须保证首个 IP 唯一。
4. 同理，小基数容差 `±1` 会正好放过「少 1」这类 off-by-one，小基数区间应当断言精确值。
