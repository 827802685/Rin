## 本轮目标：三个零覆盖的 server utils 模块（request / jwt / s3）

提交 `506f6ee`（迭代 12，6 files，+468）。修掉 3 个缺陷：

1. **`getClientIP` 采信 `X-Forwarded-For` 最左条目 → 限流可被一行 header 绕过**。
   XFF 每一跳追加，最左是调用方自己填的。影响 `auth.ts:52` 登录限流、
   `ai.ts:76` AI 聊天限流。改为取**最右**条目（真正终止连接的那一跳写入的值），
   `cf-connecting-ip` / `x-real-ip` 仍取首个，空条目跳过。
   生产在 CF 后面其实安全（`cf-connecting-ip` 优先且被覆写），
   本地开发与 Node 自托管才是真实受影响面。
2. **`jwtVerify` 未固定 algorithms** → 同一密钥下 HS512 签出的 token 会被接受。
   改为 `algorithms: [alg]`（与 sign 侧同源）。
3. **`putObject` 把 File/Blob 直接交给 S3 SDK** → Node 下抛
   `Unable to calculate hash for flowing readable stream`（请求根本发不出去）。
   此前只在 favicon 一处调用点绕开。改为在 s3 层加 `toS3Body` 统一缓冲。
