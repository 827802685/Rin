- `8a75e3f fix(server): GitHub 登录上游拒绝时返回 400 而非 500`

### 缺陷 1：授权 URL 不发 scope（静默）

`createRedirectUrl` 只拼 `client_id` + `state`，`OAuthProvider.scopes`
（GitHub 是 `read:user`）从未出现在授权请求里 —— 配置写了等于没写，
实际申请到的是空权限集合。

### 缺陷 2：两腿 redirect_uri 不一致（静默）

`authorize` 在 provider 配了 `redirectUri` 时会带 `redirect_uri`，
`createRedirectUrl` 不带。一旦有人配了 `redirectUri`，换取 token 时
提供方会以 `redirect_uri_mismatch` 拒绝。现在两腿取同一值。

### 缺陷 3：token 换取把失败当成功

`authorize` 只看 `response.ok`。GitHub 拒绝 code 时回的是
**HTTP 200 + `{error, error_description}`**，此前会返回一个
`accessToken === undefined` 的 token 对象，下游拿着它继续调 API。
现在识别 `error` 字段，并校验 `access_token` 必须存在。

### 缺陷 4：`/user/github/callback` 不检查上游响应状态

取 `https://api.github.com/user` 后直接 `response.json()`。上游返回
401 `{message: "Bad credentials"}` 时被当成正常 profile 解析，
`openid`/`username` 取到 `undefined`，最后撞 `users.openid` 的
NOT NULL 约束 —— 用户看到 500，且存在拿失败的上游认证去落库的路径。
现在非 2xx 抛 `BadRequestError('Failed to fetch GitHub user info')`。
