## Rin 迭代第三轮：parseSchema 全量接入 + callback i18n（commit 637cc2b）

### 做了什么
- **parseSchema 接入剩余 6 类接口**（moments 是上一轮已建的模式）：
  feed 创建/更新/置顶、评论创建、友链创建/更新、PUT /user/profile、POST /auth/login。
  - feed：title/content 非空、tags 必须是字符串数组、listed 必须是布尔、top 必须是数字。
    `POST /feed/top/:id` 此前**完全无校验**，top 传字符串或缺失都会直接落库，是真缺口。
  - 友链创建：长度上限 20/100/100/100 与非空由 schema 表达。顺带修掉原实现
    `name.length > 20` 在 name 为数字时恒为 undefined、可绕过长度检查的问题。
  - 登录：为保持既有断言，schema 校验失败仍抛 `Username and password are required`（原文案）。
- **契约与实现对齐**：`friendUpdateSchema` / `UpdateFriendRequest` 原把 name/desc/url 声明为必填，
  但 handler 的 `wrap()` 一直按"空则跳过"处理、实际支持单字段更新。改成交际一致的可选字段。
- **callback.tsx** 硬编码英文 `Waiting...` → `t("callback.waiting")`，四语言补齐。

### 关键做法（可复用）
- 接入 schema 前先查**客户端真实载荷**：`client/src/page/writing.tsx`、`friends.tsx` 才是
  list/draft/name 等字段是否真必填的依据，只看 schema 或只看测试都会误判。
- 状态码优先级要保：parseSchema 放在 404/403 之后，否则非管理员会先吃 400。
- 改 public/locales/*.json 用 python json.dump 会抹掉原有 CRLF/末尾无换行的写法；
  git autocrlf 会兜住，diff 仍然最小，但**必须事后 `git diff` 确认没有全文重写**。
