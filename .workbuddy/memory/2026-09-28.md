## daily-blog Day 3：分类与标签（提交 47beafb，分支 iter/2026-09-25）

- 交付：分类/标签数据模型 + 文章归类 + 前台分类页/标签页 + 后台管理页 + 编辑器分类选择与标签输入。
- 迁移 `003_taxonomy.sql` 新增 categories / tags / post_categories / post_tags。
- 关键决策：**没有**对 posts 表做 `ALTER TABLE ADD COLUMN` —— SQLite 的 ADD COLUMN 不支持 `IF NOT EXISTS`，
  重复执行报 `duplicate column name`，会破坏「迁移必须可重复执行」的约束。
  因此用 `post_categories`（post_id 为主键）表达「一篇文章至多属于一个分类」。
  → 以后在 daily-blog 里加字段时注意：要么走关联表，要么接受 ALTER 无法幂等这件事。
- 中文 slug 策略：分类/标签的中文名称**直接作为 slug**（URL 被浏览器编码但可读），
  文章仍沿用 ASCII 派生 + 时间戳兜底（中文标题会退化为 `post-YYYYMMDD-xxxxxx`）。
- 业务规则：分类名/标签名唯一；分类下仍有文章（含草稿）时禁止删除（409 并告知篇数）；标签删除只解除关联。
- 验证：`npm run migrate` OK；`npm test` 63/63；`npm start` + curl 冒烟 71/71；`git status` 干净。
- 反向验证：去掉分类查询的 `status='published'` 过滤后，「草稿不计入分类页」用例立即失败，恢复后全绿。

## 环境经验（沿用）

- 临时 shell 脚本要先 `tr -d '\r'` 规范为 LF 再执行，否则 `\` 续行失效。
- 冒烟脚本不要依赖自增主键，按 slug 从 SQLite 反查更可靠。
- `set -u` 下取参数的 shell 函数必须传全参数，否则 unbound variable 会把断言伪造成 FAIL。
- 后台表格「小屏隐藏第 3 列」的全局 CSS 规则需要类名限定，否则会误伤新增的 3 列表格。
