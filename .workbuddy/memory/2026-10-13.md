## 新经验（重要）

- **bun 的 `mock.module` 会跨测试文件残留**：只替换 `getStorageObject` 一个导出，
  同进程的 rss / storage / cache 用例拿到残缺模块，全量跑出 4 条与本轮无关的假红。
  改用 env 注入假 `R2_BUCKET`（storage 层在 `R2_BUCKET` 存在时直接走 `bucket.get()`），
  零全局污染。**优先用 env 注入而不是模块 mock。**
- **断言「被安全机制挡下」必须让被挡对象真的存在**：首版 traversal 用例里假 R2
  预置 key 写错（`../evil` vs 实际 `../../evil`），对象取不到走「不存在」分支，
  与被过滤的 skipped++ 计数完全相同 → 变异 SURVIVED 的假绿。
- **别和 client vite build 并发跑 server test**：同机并发会出 3 fail / 3 errors
  （超时型），单独重跑即 0 fail。判定回归前先串行重跑一次。
- 仓库源码是 **LF**，不是 CRLF（git 的 `LF will be replaced by CRLF` 警告可反推）；
  变异脚本继续用「先探测行尾」的老办法。
